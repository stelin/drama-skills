## 聚合的输入只有提取

S3/S4 只读 `章节/*-提取.md`，不回头重读原文。回头重读会产生第二份事实：同一个人物在
提取层叫一个名字、在聚合层叫另一个，而两层都说自己对。

章数多、上下文放不下时按章号分批读，每批产出中间归并结果，再归并中间结果。分批边界
要落在 `_progress.md` 里，让续跑能对齐。

## 剧情单元

**单元不是章。** 一个单元是有始有终的一段压力：进入状态 → 冲突与升级 → 代价 →
出去状态。它可能横跨十二章，也可能一章装两个。

两步法，顺序不能反：

1. 先从全部提取里**识别单元边界**，只写单元清单与每个单元一句话的戏剧命题；
2. 再把情节点**分配**进单元。

先分配再总结，会让单元变成章节的重新装袋——每个单元恰好等于若干整章，这本身就是没做
第一步的信号。

每个单元记录：

| 字段 | 内容 |
|---|---|
| 进入状态 | 谁想要什么、手上有什么、受什么限制 |
| 冲突来源 | 谁或什么在反制，为什么主角不能退出 |
| 升级 | 每一轮改变了权力/信息/关系/暴露/资源/时间/代价里的哪一项 |
| 代价 | 主角为推进付出了什么，是否当场兑现 |
| 出去状态 | 结束时哪些事实变了，下一单元必须继承什么 |
| 来源 | 章号区间与情节点 ID |

没有升级、只是把同一件事重复得更响的单元，写明「无升级」——这正是改编时最该压缩的段落。

## 节奏与情绪

`节奏与情绪.md` 三段：

- **关键信息推进**：一条信息从被埋下到被读者知道、再到被角色知道，各在第几章。
  信息在角色之间的不对称是短剧最便宜的张力来源，值得单独成表。
- **情绪触动点**：每个爽点/虐点/期待点写铺垫→释放→余波三段位置。只有释放没有铺垫的
  触动点，在短剧里会变成观众看不懂的突然发作。
- **伏笔与兑现**：埋点位置、兑现位置、未兑现的列成清单。未兑现不是缺陷，
  是改编时可以自由处置的余量。

**不设跨项目的频率阈值。** 每隔几章一个爽点是项目自己的选择，不是本表能判定的缺陷。
本表只呈现分布，由创作者判断。

## 人物归并

跨章归并，三步：

1. **候选收敛**：按称谓、别名、身份线索聚合。同一人的不同称谓（本名、绰号、职务、
   亲属称呼）收敛为一条，保留全部原始称谓。
2. **置信度**：能被至少两处独立提取互相印证的归并标记 `resolved`；只有单处线索的
   标记 `unresolved` 并写明依据。**不要为了让人物表干净而把 `unresolved` 提成
   `resolved`**——错误的归并会把两个人的动机缝成一个自相矛盾的人。
3. **分级**：主角 / 对抗方 / 核心配角 / 功能角色。分级依据写出来：谁迫使主角作选择、
   谁持有证据或资源、谁只承担一次性功能。

每条人物记录带：全部称谓、首次出现章、承担的功能、知情范围、关系压力、来源引用、
以及 `resolved | unresolved`。

关系从**情节点**提取，不从原文——原文里的关系描写常常是叙述者的判断，情节点里的关系
是行为证据。关系有演变时记录演变位置与最终状态。

## 设定归纳

从提取的提及数据归纳，不从原文重扫：世界规则、力量或资源体系、势力与其利害、
地理与空间限制、以及主角的特殊条件（若有）及其边界与代价。

内容不足以独立成节的势力或规则，合并进背景设定，不要为了目录整齐建空文件。

## 事实可溯源自检

S3/S4 的产物离原文两跳，是事实漂移最大的来源——模型会用合理性填空，而且填得很像真的。

进入 S5 前逐条检查：设定、人物与单元里的**硬事实**（数值、等级、距离、时间、
属性、势力数量、谁说过什么、谁在第几章出现）必须能回溯到某条情节点的白描段。

回溯不到就改写成「原文未明确」。**禁止推断填空**。一个写着「原文未明确」的字段，
下游可以决定要不要补;一个被填出来的假事实，下游没有任何办法发现。
