# 术语表：字段名和固定标识里的词怎么读

本套件的字段名、状态值和文件名是稳定标识，不随语言设置翻译，也不会为了读起来顺就改写。
它们出现在正文里时保持原样，本表只解释**每个词在本套件里指什么**，供第一次读到时对照。

正文写给创作者的部分用日常词；只有下面这些词因为同时是字段名或文件名才保留原形。
如果一段正文除了这些词之外还很难读，那是正文的问题，不是术语的问题。

## 生命周期与依赖

| 词 | 在本套件里指什么 |
|---|---|
| `accepted` | 创作者已经接受的版本。只有它能作为下游的输入依据 |
| `candidate` | 还没被接受的候选版本。可以预览、可以被替换，不能当作依据 |
| `stale` | 上游改了、这份下游文件因此过期。不是"文件坏了"，是"要重新核对" |
| `delta` | 两个状态之间的差，例如某个道具从完好到破损的那次变化 |
| `occurrence` | 某个角色、地点或道具在剧本里出现的一次，带来源块引用 |
| `disposition` | 一条原文要求当前被怎么处理了：谁承担、落在哪个字段、还是明确放弃 |
| `provenance` | 一条信息的来路：谁提供的、什么时候、经过谁确认 |
| `WAL` | 预写事务日志。先写清单再动文件，中断后能按清单恢复 |
| `hash` | 文件或记录的内容指纹。内容变了指纹就变，用来发现上游改动 |

## 各环节的产物

| 词 | 在本套件里指什么 |
|---|---|
| `triage` | 分诊。读小说时先做的快速评估，判断值不值得花全量拆解的成本 |
| `coverage` | 一场戏被哪些镜头覆盖到了，以及有没有漏 |
| `audition` | 试拍方案对比。同一场戏先摆几种拍法供创作者挑，不是最终分镜 |
| `plate` | 单张参考图。地点 plate 和道具 plate 各自只交代一个对象的稳定外观 |
| `lookdev` | Look Development 的简称。正式分镜前先用少量代表帧定下全片视觉语言 |
| `rubric` | 评分细则。审查时逐条对照的问题表，不是打总分 |
| `fixture` | 固定样例。写在文档里的正例/反例，用来对齐判断尺度 |
| `motion` | 一个镜头的运动说明，交给视频生成器执行 |
| `container` | 交付容器。若干镜头按顺序打包成一段可交付内容 |

## 规则分级

| 词 | 在本套件里指什么 |
|---|---|
| `structural_invariant` | 脚本能当场验证的硬要求，不满足就拦下 |
| `reviewed_invariant` | 需要人或独立审查者引用证据判断的要求，可以拦下交付 |
| `craft_default` | 通常有用的默认做法，创作者说明理由就能覆盖 |
| `taste_option` | 口味选项，只提供选择，本身从不拦下任何东西 |
